ESP32 AutoMesh v0.3.17-dev — обновления через веб-панель шлюза

ШЛЮЗ (Web-OTA/):
  gw-c3.bin      ESP32-C3 SuperMini 4MB
  gw-s3.bin Waveshare ESP32-S3-Zero 4MB

УЗЛЫ (Web-OTA/Nodes/):
  node-c3.bin      ESP32-C3 SuperMini 4MB
  node-s3.bin Waveshare ESP32-S3-Zero 4MB

SHA256SUMS.txt в этой папке содержит контрольные суммы всех четырёх
файлов и относительные пути к ним.

ОБНОВЛЕНИЕ ЛЮБОГО УСТРОЙСТВА — ОДИН РАЗДЕЛ:
1. Откройте веб-панель шлюза и войдите.
2. Выберите ШЛЮЗ или ОДИН доступный узел с поддержкой OTA1.
3. Выберите полный ZIP релиза AutoMesh либо подходящий APP .bin
   из папки Web-OTA; панель автоматически выберет нужный файл из ZIP.
4. Браузер проверит чип C3/S3, роль, версию и вычислит SHA-256.
   Несовместимая прошивка не будет отправлена.
5. Нажмите «Обновить» ОДИН раз. Следите за прогрессом и дождитесь
   подтверждения проверки и перезапуска ESP32.

Дополнительные сведения:
- Для устаревших узлов без OTA1 нужна однократная прошивка по USB.
- Обновление узла через BLE Mesh медленнее Wi-Fi обновления шлюза.
- Если браузер не умеет распаковывать ZIP (deflate-raw), выберите .bin.
- NVS, настройки Wi-Fi и Mesh-ключи при OTA не очищаются.
- Нет автоматической массовой установки или смены шлюза.

БЕЗОПАСНОСТЬ:
- Не отправляйте бинарник шлюза узлу или узла шлюзу.
- Передача допускается только авторизованным администратором.
- Узел сверяет SHA-256, чип, тип приложения и OTA-образ до перезапуска.
- Изменения касаются только неактивного APP-раздела, без стирания NVS.
- При прерванной передаче старая прошивка продолжает работать.
- Протокол экспериментальный; проверяйте на одном тестовом узле.
- Массовая автоматическая OTA, резервный провиженер и принудительное
  переподключение Mesh здесь не реализованы.

Имена OTA-образов сокращены: gw-c3.bin, gw-s3.bin,
Nodes/node-c3.bin и Nodes/node-s3.bin. «gw» — шлюз,
«node» — узел, «c3/s3» — тип ESP32. Сам USB-установщик
продолжает использовать официальные имена файлов ESP-IDF.

При обновлении шлюза v0.3.13-dev из нового ZIP сначала
распакуйте ZIP на компьютере и выберите .bin (gw-c3.bin/gw-s3.bin):
старый браузерный интерфейс ищет длинные имена внутри ZIP.
После установки v0.3.14-dev можно выбирать ZIP целиком;
новая панель понимает и старые, и короткие имена.

v0.3.15-dev — исправления Mesh OTA:
- Узлы обрабатывают запись OTA во FreeRTOS worker, не блокируя
  BLE Mesh callback. Стирание Flash последовательное.
- Шлюз повторяет потерянные START/DATA сообщения до трёх раз,
  ожидает подтверждения и сообщает точный этап ошибки.
- При обновлении одного узла приостанавливаются обычные
  периодические проверки связи с другими узлами шлюзом.
- При ошибке тайм-аута на уже установленном старом узле может
  потребоваться обновить его по USB с сохранением NVS.
- Настройки Wi-Fi перемещены к низу страницы.

v0.3.16-dev — все четыре бинарных APP-файла обновлены для
новой вкладки «Карта Mesh». Для отображения прямых радиососедей
обновите прошивки шлюза и каждого узла (через веб, если OTA1 работает,
либо по USB с сохранением NVS). Данные RSSI собираются по TTL=1
и не являются гарантированным маршрутом пакета.


v0.3.17-dev — ПОЧЕМУ БЫЛ ESP_ERR_TIMEOUT УЗЛА:
- Был пропущен тип события ESP-IDF RECV_PUBLISH_MSG_EVT для
  непривязанного к op_pair ответного статуса OTA. Шлюз посылал
  команду, но не принимал подтверждение, даже когда узел отвечал.
- В новой версии шлюза оба типа статусов обрабатываются, с
  проверкой адреса, ID сессии и смещения.
- На новой прошивке узла ответы OTA имеют TTL=5, чтобы проходить
  через ретрансляторы. Старым узлам это изменение по воздуху
  недоступно до первой успешной прошивки.
- Сначала обновляйте шлюз, затем тестовый узел поближе к шлюзу.
  Если первый OTA узла не удаётся, используйте USB без очистки NVS.
