AutoMesh — первичная установка прошивок ESP32 для Windows
Версия пакета: 0.3.21-dev

Поддерживаемые профили:
  ESP32-C3 SuperMini, Flash 4 MB (GPIO8, обычный active-low LED).
  Waveshare ESP32-S3-Zero с USB Serial/JTAG, Flash 4 MB;
            WS2812 RGB светодиод на GPIO21, аппаратный RMT.
Дополнительная PSRAM на S3 не обязательна, не используется приложением.

БЫСТРЫЙ ЗАПУСК
1. Подключите ESP32 к ПК через USB-кабель с поддержкой передачи данных.
2. Запустите Install-AutoMesh.cmd или AutoMesh-Installer.exe.
3. Установщик автоматически обнаружит USB COM-порты, определит тип ESP32,
   MAC и действительный размер Flash средствами esptool.
4. Программа подберёт отдельные совместимые образы для вашего чипа и Flash.
   Если совпадения нет — ОТКАЖЕТСЯ прошивать чужую сборку.
   Распиновку светодиода и функциональную роль чип автоматически НЕ определяет.
5. Выберите роль: Шлюз или Узел. Если на плате ранее был AutoMesh,
   установщик покажет прежнюю роль по резервной копии.
6. Программа проверяет SHA-256 и чип, делает ПОЛНУЮ резервную копию Flash,
   затем просит ОДНО окончательное подтверждение: нажмите 1.
7. NVS по умолчанию сохраняется (вместе с Mesh-ключами и настройками).
   Очистка NVS доступна только через специальный параметр --erase-nvs.
8. Записываются загрузчик, таблица разделов, OTA-метаданные и приложение.

КОМАНДЫ
  AutoMesh-Installer.exe --check
  AutoMesh-Installer.exe --port COM16 --check
  AutoMesh-Installer.exe --port COM16 --role node
  AutoMesh-Installer.exe --port COM16 --role gateway

--check НЕ изменяет содержимое Flash и не делает резервную копию.
Обычная установка: выбор COM-порта, выбор роли и одно подтверждение [1].
При --port и --role нужен только один ответ [1] перед записью.
--erase-nvs — опасный отдельный режим, стирает настройки и Mesh-ключи.
AutoMesh-Installer.exe не требует установленного Python.
installer.py при запуске из исходника требует esptool + pyserial.

ВНИМАНИЕ
  ESP32-S3 выпускается с разным объёмом Flash (4/8/16 МБ), вариантом
  PSRAM, типом встроенного LED (обычный или адресный RGB) и GPIO.
  В комплект вошла отдельная компиляция ESP32-S3 с Flash 4 МБ.
  Для ESP32-S3 с 8/16 МБ нужны дополнительные профили и проверенные
  сборки с подходящей разметкой; данный установщик НЕ станет подменять их
  четырёхмегабайтной прошивкой.
  Профиль S3 предназначен именно для Waveshare ESP32-S3-Zero 4 МБ:
  его RGB-светодиод подключён на GPIO21. Для других плат S3 GPIO21
  может использоваться иначе — не устанавливайте этот профиль.
  Bluetooth Mesh и веб-панель шлюза в прошивку включены.

  НЕ отключать питание/USB во время Flash-записи.
  Резервные копии сохраняются в %LOCALAPPDATA%\ESP32-AutoMesh\Backups.
  Они могут содержать Wi-Fi пароли и секретные Mesh-ключи.
  Не публикуйте их в GitHub или общем архиве с прошивками.
  Готовые образы проверены при сборке, но первая установка на ESP32-S3
  физически не проведена и не заменяет тестирование устройства.

  Не используйте Bluetooth Mesh web-панель из открытого интернета без
  дополнительно защищённого подключения. Веб-панель требует админ-токен.



ESP32-S3: профиль Waveshare ESP32-S3-Zero с 4 МБ Flash.
Установщик умеет автоматически распознать S3 и подобрать отдельно
собранную прошивку шлюза или узла. Это не означает автоматическое
определение распиновки платы: RGB-светодиод WS2812 управляется через RMT на GPIO21.
Для других ESP32-S3 требуется отдельный профиль с проверенной распиновкой.
Команда проверки без записи: AutoMesh-Installer.exe --self-test
Для проверки подключённой платы: AutoMesh-Installer.exe --port COM16 --check
ВНИМАНИЕ: доступен только профиль Flash 4 МБ. Не используйте его для
плат ESP32-S3 с Flash 8/16 МБ. Резервная копия обязательна.


НОВЫЙ ШЛЮЗ: при отсутствии сохранённого Wi-Fi устройство создаёт открытую
сеть AutoMesh-XXXXXX без пароля. Откройте http://192.168.4.1/ и задайте
собственный ключ администратора от 6 символов. Он хранится в NVS шлюза
как PBKDF2-хеш и переживает перезапуск. Для уже настроенных шлюзов
старый 32-символьный токен сохраняется до ручной смены в веб-панели.
Сеть без пароля небезопасна: настройте администраторский ключ и роутер
в контролируемом месте без посторонних поблизости.


Исправление v0.3.8-dev: неверный ключ администратора больше не вызывает
повторяющиеся запросы из браузера и блокировку HTTP 429. При 401 панель
удаляет неверный ключ и предлагает вход. При 429 показывает время
ожидания. Ключ администратора и настройки Mesh в NVS не удаляются.



v0.3.8-dev: регистрация нового узла теперь выполняется нажатием
«Разрешить» после входа в шлюз. Отдельный OOB-код не нужен.
Обязательно прошейте новую версию на шлюз и на узел, иначе
старый узел может требовать статический OOB. Без OOB соединение
подвержено активной подмене при регистрации в радиозоне.


Выбор контроллера и веб-обновление шлюза (v0.3.8-dev)

Установщик показывает все подключённые ESP32. Выбор COM-порта
обязателен даже при единственном подключённом устройстве. После выбора роли проверяются SHA-256 и совместимость образов,
сохраняется полный дамп Flash и выводится итоговый экран.
Одно подтверждение [1] разрешает запись. Повторный ввод COM не нужен.
MAC и модель контроллера автоматически перепроверяются перед записью.

В архиве есть отдельная папка Web-OTA для обновления шлюза через веб:
  Web-OTA/gw-c3.bin
  Web-OTA/gw-s3.bin
  Web-OTA/SHA256SUMS.txt и Web-OTA/README-RU.txt.
Из авторизованной панели шлюза отправляйте только файл с вашим чипом.
Сама ESP32 повторно проверяет тип и контрольную сумму прошивки.
На устройствах без встроенного Web OTA сначала установите пакет USB.
Ключи Mesh, имена и настройки Wi-Fi при OTA не стираются.
Это не прошивка удалённых узлов по BLE Mesh.

v0.3.9-dev: упрощена установка USB — выбор контроллера, роли и
один ответ [1] для запуска записи. Резервная копия, проверка SHA-256,
совместимости образов и повторная идентификация ESP32 обязательны.
Очистка NVS убрана из обычного сценария, требуется --erase-nvs.

v0.3.10-dev: в ZIP добавлена папка Web-OTA с двумя бинарниками
обновления шлюза и SHA-256. Веб-панель показывает версию и ID сборки,
прочитанные из реально запущенного образа шлюза. Для узлов v0.3.10-dev
шлюз автоматически запрашивает версию по BLE Mesh и отображает ответ.
Более старые узлы не поддерживают запрос: версия останется неизвестной,
пока узел не обновят через USB. Удаленное обновление узлов через веб
пока не реализовано.

v0.3.12-dev — Mesh OTA узлов:
  В Web-OTA/Nodes находятся образы узлов для C3 и Waveshare S3-Zero.
  Откройте авторизованную веб-панель шлюза, выберите один узел OTA1,
  затем соответствующий файл onoff_server.bin. Загрузка идёт через
  шлюз по BLE Mesh небольшими подтверждаемыми пакетами, медленнее Wi-Fi.
  Старые узлы без OTA1 надо ОДИН РАЗ обновить по USB.
  OTA узла записывает только неактивный APP-раздел и сверяет SHA-256,
  чип и название проекта. NVS/Mesh-ключи сохраняются.
  Не выключайте питание; не закрывайте веб-страницу до окончания.
  Автоматического обновления нет. Один узел за один сеанс.
  Изолированная Mesh-сеть продолжает работать без шлюза: Relay включён
  на узлах, они обмениваются контрольными сообщениями peer-to-peer.
  Без шлюза недоступны веб-управление, допуск новых узлов и обновления.

v0.3.12-dev — интерфейс шлюза:
  UUID скрыт из таблицы, OTA-списка и сообщений. Внутренние API
  продолжают использовать UUID, чтобы не перепутать контроллеры.
  В строке зарегистрированного узла есть кнопка «Удалить устройство».
  После подтверждения удаляются запись Provisioner и локальная запись
  шлюза, включая старый NVS-кеш. Удаление подтверждается callback Mesh,
  при ошибке запись остаётся в списке.
  ВНИМАНИЕ: удаление из шлюза не удаляет Mesh NetKey из памяти самого
  узла! Перед повторной регистрацией необходим сброс настроек Mesh
  на удалённой ESP32, а при необходимости — ротация ключей всей сети.

v0.3.13-dev — единое обновление через веб-интерфейс:
  Выберите ШЛЮЗ или один зарегистрированный УЗЕЛ с поддержкой OTA1.
  Откройте весь ZIP-архив GitHub Releases либо один подходящий APP .bin
  из Web-OTA. Браузер сам распакует нужный бинарник и прочитает
  chip_id (C3/S3), project_name (provisioner/onoff_server) и версию.
  Неподходящий файл будет отклонён до отправки. Нажмите «Обновить».
  SHA-256 вычисляется автоматически, никаких ручных технических полей,
  дополнительных окон подтверждения или выбора второго OTA-раздела.
  Прогресс передачи показывается в одном месте; при Mesh OTA можно
  остановить передачу после текущего блока. Mesh-ключи/NVS сохраняются.
  ВАЖНО: некоторые браузеры не умеют распаковывать ZIP с deflate-raw,
  в них используйте отдельный .bin из Web-OTA.
  Старые узлы без OTA1 всё ещё нуждаются в первоначальной USB-прошивке.

v0.3.15-dev — исправление тайм-аутов Bluetooth Mesh OTA:
  Если узел отвечает «ESP_ERR_TIMEOUT» при веб-обновлении, обновите
  ПО шлюза и узла до v0.3.15-dev. В предыдущей прошивке операции
  предварительного стирания Flash выполнялись внутри Mesh callback,
  что могло задерживать или терять ответ. Теперь они выполняются
  в отдельном FreeRTOS OTA worker, а esp_ota_begin использует
  OTA_WITH_SEQUENTIAL_WRITES. Шлюз повторяет START и DATA до трёх
  раз при пропаже подтверждения, и не создаёт фоновый радиоопрос
  узлов во время OTA.
  Веб-панель показывает этап ошибки: начало/передача/завершение/отмена.
  Если узел со старой прошивкой всё равно не отвечает при старте,
  прошейте его v0.3.15-dev по USB, сохраняя NVS/Mesh-ключи. Не
  сбрасывайте устройство и не очищайте ключи без резервной копии.
  Настройки Wi-Fi перенесены к низу веб-панели, перед сменой пароля
  администратора.
  Обновляйте ПО по одному тестовому узлу; реальные аппаратные
  испытания на случай пропажи питания и OTA rollback обязательны.

v0.3.16-dev — интерактивная «Карта Mesh»:
  Отдельная вкладка показывает зарегистрированные узлы шлюза,
  измеренные прямые радиососедства, RSSI, состояния и свежесть
  наблюдений. Узлы можно перемещать на схеме, менять масштаб и
  обновлять карту. Радиомаяки TTL=1 не пересылаются соседями, поэтому
  линии отражают только непосредственные радиоконтакты, не маршруты.
  Старые узлы без новой функции видны без фиктивных линий.
  Узлы должны быть обновлены до v0.3.16-dev, лучше один за другим.
  История и схема не записываются в NVS, Mesh-ключи сохраняются.


v0.3.17-dev — исправление Bluetooth Mesh OTA узлов:
  Исправлена потеря подтверждений OTA на шлюзе. При отправке
  неаккумулирующих сообщений need_rsp=false ESP-IDF передаёт
  ответ узла в CLIENT_MODEL_RECV_PUBLISH_MSG_EVT, а прошлый
  шлюз слушал только MODEL_OPERATION_EVT. Исправлены оба пути,
  сохранена проверка адреса, сессии и подтверждённого offset.
  Узел теперь отправляет STATUS с явно заданным Mesh TTL=5,
  чтобы ответ проходил через промежуточные ретрансляторы.
  В UART-логах отображаются подтверждения START и ошибки отправки.

  Порядок обновления: СНАЧАЛА прошить шлюз v0.3.17-dev через веб
  с помощью gw-c3.bin или gw-s3.bin. После этого попробовать
  обновить ОДИН находящийся рядом узел через веб (node-c3.bin
  или node-s3.bin). Обновление не запускается автоматически.
  Если узел прежней версии не отвечает через ретрансляторы,
  его первый переход на исправленную прошивку может потребовать
  USB без очистки NVS/ключей.
  Сборка CI не подтверждает фактическую работу на железе;
  требуется испытать на настоящих ESP32 и проверить rollback.


v0.3.18-dev — новая структура веб-панели шлюза:
  «Устройства» — список устройств, допуск и обновление прошивок.
  «Карта Mesh» — только интерактивная карта, без других разделов
  и кнопок (мышь: перетаскивание, колесо: масштаб, двойной клик: сброс).
  «Настройки» — сканирование и подключение Wi-Fi, смена ключа
  администратора. Результаты действий видны внутри настроек.
  Удалён раздел «Радиосвязь и индикация».
  На первом запуске после создания администратора вкладка
  «Настройки» открывается автоматически.
  Алгоритм Mesh и обновления узлов не изменён.


v0.3.19-dev — ускоренный Mesh OTA:
  Шлюз выбирает размер DATA автоматически по версии узла:
  OTA1 = 96 байт (полная совместимость), OTA2 = 224 байта.
  Старым узлам новый размер НЕ передаётся. Веб-панель показывает
  скорость и примерное оставшееся время.
  ВАЖНО: первый переход старого узла на OTA2 по Bluetooth останется
  медленным. Для экономии времени используйте Windows USB-установщик,
  НЕ выбирая очистку NVS/Mesh-ключей. После перехода на OTA2 можно
  проверить ускоренное обновление по BLE Mesh.
  Реальная скорость зависит от радиоэфира и числа Relay; 224-байтные
  блоки сами сегментируются BLE Mesh и не гарантируют ускорения.


v0.3.20-dev — карта Mesh:
  По нажатию на устройство открывается меню с состоянием,
  версией, обнаруженными прямыми соседями, RSSI и кнопкой
  «Найти устройство» (мигание светодиода, 15 секунд).
  Меню можно дополнять другими действиями позже.
  Исправлено скрытие реальных TTL=1 связей при неизвестном RSSI:
  линия с неизвестным RSSI серая, число dBm не выдумывается.
  Для прямых связей нужны прошивки узлов, поддерживающие карту.
  Никакая история не записывается в память ESP32.

v0.3.21-dev — короткая версия в веб-интерфейсе:
  В таблице «Устройства» и меню карты показывается только
  номер версии и тип контроллера, например «0.3.21-dev C3».
  Маркер OTA1/OTA2 и технический хеш не удаляются из протокола:
  шлюз по-прежнему определяет поддерживаемый размер OTA-блока.
