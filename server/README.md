# AutoMesh Server — тестовая версия для Windows и Linux

Это первый этап переноса логики ESP32 AutoMesh на компьютер. В каталоге server находится .NET 10 веб-сервер с физическим USB-подключением ESP32-C3/S3.

**Уже реализовано:** выбор COM/tty-порта, локальная веб-панель, автопереподключение, получение состояния Mesh-устройств и ручное подтверждение/отклонение новых узлов. Компьютер не является вторым Mesh Provisioner: ключи NetKey/AppKey остаются в NVS самой ESP32.

**Ещё не реализовано:** серверное OTA с возобновлением после закрытия страницы, MQTT, SQLite, интерактивная карта, сетевой доступ с HTTPS, несколько Provisioner и Windows/Linux системная служба. Первую версию следует проверять на одном тестовом шлюзе.

## Первый запуск

1. Установите на ESP32-шлюз прошивку **v0.3.26-dev**, подходящую для ESP32-C3 или ESP32-S3. Узлам новую прошивку ставить не требуется. НИ В КОЕМ СЛУЧАЕ не включайте очистку NVS, если хотите сохранить сопряжённые устройства.
2. Подключите шлюз USB-кабелем к ПК. Закройте IDF Monitor, esptool и другие программы, занимающие тот же порт.
3. Скачайте AutoMesh-v0.3.26-dev.zip из GitHub Releases. Внутри раздела Server будут два готовых архива: AutoMesh-Server-windows-x64.zip и AutoMesh-Server-linux-x64.tar.gz. Распакуйте подходящий для своей ОС.
4. На Windows запустите AutoMesh.Server.exe. На Linux дайте разрешение на запуск (chmod +x AutoMesh.Server) и выполните ./AutoMesh.Server. .NET SDK не нужен, сборки автономные.
5. Откройте http://127.0.0.1:8765 в браузере на том же компьютере. Скопируйте токен администратора из консоли сервера.
6. Выберите USB-порт ESP32 (COM12 или /dev/ttyACM0 — примеры), нажмите «Подключить ESP32» и затем «Включить USB Mesh». Контроллер перезапустится и будет работать через USB без Wi-Fi.
7. В списке устройств выберите неизвестный узел и нажмите «Разрешить». Как и раньше, регистрация неизвестных узлов невозможна без подтверждения администратора.

Если шлюз уже подключён к маршрутизатору по Wi-Fi и Mesh работает, USB-команды можно использовать и без USB-only режима. «Вернуть Wi-Fi-режим» возвращает встроенную веб-панель, не стирая Mesh-ключей.

## Восстановление режима

В специальном USB-only режиме шлюз не включает Wi-Fi. Режим сохраняется в NVS до команды USBMODE 0 через физический USB-порт. Не стирайте NVS ради выхода из этого режима. Если сервер не может открыть порт, закройте другие программы, использующие COM, и проверьте драйвер и кабель.

Существующие зарегистрированные узлы не будут показываться как новые. Уже присвоенные Mesh-ключи остаются на них: не выполняйте массовое стирание NVS для «повторного сопряжения».

## Безопасность

По умолчанию сервер слушает только 127.0.0.1:8765. HTTP-API требует заголовок X-AutoMesh-Admin с секретным токеном. Секрет создаётся при первом запуске в пользовательском каталоге конфигурации AutoMeshServer/admin.token, либо передаётся переменной окружения AUTOMESH_SERVER_TOKEN (не менее 12 символов).

Выставлять AUTOMESH_LISTEN на 0.0.0.0 для использования через интернет НЕ следует без HTTPS, дополнительных средств защиты и проверки аутентификации. Физический доступ к USB/COM — привилегированный доступ к Mesh Provisioner.

При необходимости выбрать USB порт при запуске: переменная AUTOMESH_USB_PORT (например COM12 или /dev/ttyACM0). Автоматическое открытие произвольных COM-портов намеренно отключено, чтобы не управлять чужими контроллерами.

Linux: нужны права чтения и записи для /dev/ttyACM* (часто группа dialout). Windows: используется системный COM-драйвер.

## Сборка из исходников

Для самостоятельной сборки нужен .NET SDK 10:

Windows:
dotnet publish server/AutoMesh.Server.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false -o output/win-x64

Linux:
dotnet publish server/AutoMesh.Server.csproj -c Release -r linux-x64 --self-contained true -p:PublishSingleFile=true -p:PublishTrimmed=false -o output/linux-x64

## Протокол ESP32/ПК (USB v1)

ESP32 принимает HELLO, LIST, APPROVE <uuid>, DENY <uuid>, USBMODE 1 и USBMODE 0. Ответы и уведомления выдаются отдельными строками с префиксом AUTOMESH и JSON после пробела.

События: ready, candidate, device, snapshot_begin, snapshot_end, provisioned, approval_started, denied, error, usb_mode_changed. Записи журнала ESP-IDF без префикса AUTOMESH сервер игнорирует.

Из-за особенностей USB Serial/JTAG одна программа должна владеть COM-портом. Во время прошивки закройте сервер. После обновления сервер сможет переподключиться к выбранному порту.
