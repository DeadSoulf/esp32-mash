# Режим Mesh без шлюза — текущее и планируемое

1. ESP32-C3/S3 узлы имеют `CONFIG_BLE_MESH_RELAY=y` и
   `ESP_BLE_MESH_RELAY_ENABLED`. Участники хранят NetKey/AppKey,
   адреса, sequence/replay и конфигурацию в NVS.
2. Приложение Node v0.3.11-dev отправляет редкие AppKey-защищённые
   PEER_HELLO в All-Nodes с TTL=4. Соседний Node хранит в RAM
   последние адреса/время контакта (окно 180 с) и отмечает
   присутствие других Mesh-участников. Таким образом LED может
   показывать связь с соседями даже при выключенном шлюзе.
3. Сам механизм переадресации/ретрансляции пакетов обеспечивает
   штатный стек BLE Mesh. Когда один узел выходит из строя, трафик
   может проходить другими Relay-узлами, если физически существует
   альтернативная связная цепочка; **это не гарантия покрытия**.
4. Если шлюз выключен: узлы продолжают принимать PEER_HELLO и
   ретранслировать Mesh-пакеты, но веб-панель, админ-команды,
   регистрация новых узлов и обновление прошивок недоступны.
5. Другого Provisioner или автоматической передачи полномочий
   в проекте сейчас нет. Для настоящего failover шлюза необходимо
   безопасно синхронизировать NetKey, AppKey, IV index, sequence,
   node database, распределить права администратора и исключить
   два независимых Provisioner с одинаковым адресом.
6. Проверять на реальном оборудовании минимум с тремя узлами:
   связь A↔B↔C, затем выключение шлюза, затем B, затем возврат B;
   следить за relay/TTL, логами peer beacon и отсутствием потери NVS.
